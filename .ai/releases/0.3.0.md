# download-media 0.3.0

This release adds `--playlist-items`, makes the wizard handle several URLs and login walls, embeds subtitles, and stops reporting saved files as failures, or failures as success.

## What you need to do

- **AUR users:** update as usual. No dependency changed.
- **Scripts that shorten `--playlist`:** in 0.2.0, `--p` through `--playlis` meant `--playlist`. They are now ambiguous with `--playlist-items` and exit 2. Write `-p` or `--playlist` in full.
- **Scripts that rely on exit codes:** a `-p` run in which every item fails now exits 1, where it said `Done.` and exited 0. Files that were saved without tags, or without a cover image, now exit 0, where they reported `Download failed` and exited 1.
- **`-p` on a URL that holds a single video:** the file is now named as without `-p` (`<title>.mp4`), not `NA - <title> [<id>].mp4`. Running such a download again after upgrading saves one new copy next to the old file.

No flags were renamed or removed, no defaults changed, and your history file stays where it is.

## New

- **`--playlist-items`** downloads only some items of a playlist or carousel, for example `--playlist-items 1-3,5`. Items that aren't in the list are named in the output. With `-i`, the wizard's item picker starts from them.
- **Subtitles are embedded.** `-s` now puts the subtitles inside the video, and still saves the subtitle files. `--sub-langs` alone now turns subtitles on. In mp4 the first language is marked as the default track; mkv and webm mark none.
- **The wizard walks every URL you pass,** not only the first one, then downloads them all. It says at the end which ones it skipped.

## Changed

- **The command printed after a run** always carries `-y` and stays in direct mode, so it repeats the run without any prompt. It is no longer printed after a cancelled run.
- **Cookies in the wizard.** When the probe hits a login wall, the wizard asks for cookies and shows the site's reason. Instagram is no longer asked for cookies before the probe: public posts go straight to the item picker, and a post that needs a login asks once, after the probe. X and Facebook still ask up front, and the running summary now shows that answer.
- **Audio pages in the wizard.** `.m4a` and `.wav` pages, and `.ogg` pages whose source names an audio codec, now convert to your audio format in `~/Music`. They used to land as they were in `~/Videos`.
- **Audio labels on video containers.** When a server or page labels a file as audio but its container can hold video (`.ogg`, `.wma`, `.m4b`, `.asf`, `.mp4` or `.webm`, sent as `audio/*` or in an `<audio>` tag), the wizard shows `Audio` with a note and asks video or audio. Enter keeps the file as served in `~/Videos`, as 0.2.0 and `-y` do; `2` gives an mp3. An `<audio>` tag on a file with no extension asks the same question. `.mp3`, `.m4a`, `.wav`, `.flac`, `.aac` and `.opus` keep the audio flow and convert to `~/Music`.
- **Cover images** are fetched as `<name>.cover.<ext>`. `-a` no longer deletes your own `<title>.jpg` in the output folder; a file already named `<title>.cover.jpg` is still replaced.

## Fixed

- **Files saved but reported as failed.** Files ffmpeg can't write tags to (`.ogx`, `.weba`, `.m4r`, `.f4a`, `.f4b`, links with no extension, renamed files) now end in `Done.`, with a warning that the file has no metadata and that running the same download again may save a second copy. `-p` no longer counts such items twice.
- **`-a` failing over the cover image.** A page whose image link is relative crashed with a traceback. `-f opus` on systems without `python-mutagen`, and a broken image, failed the download with the audio already on disk. All of these now save the audio and say `<file>: saved without a cover image.` `-f wav`, which can't hold a cover, no longer asks for one, so it no longer fails on every video that has a thumbnail.
- **Leftover thumbnails.** Thumbnails are no longer left behind after a failed download, and a playlist's own thumbnail is no longer saved next to its tracks.
- **A browser that isn't installed, or whose cookies can't be read.** The run now says so and goes on without cookies, in every mode. `-p`, `--playlist-items` and the item picker used to end in a traceback; `-l` used to fail. Single downloads no longer say `Failed with <browser> cookies` or suggest a keyring that doesn't apply, and the printed command leaves out `--cookies` when the run saved without them.
- **An output folder that can't be created** (`-o` on a file, a read-only or missing parent) no longer ends the run in a traceback. That URL says `Can't save to <folder>: <reason>. Choose another folder with -o.` and fails; the other URLs still run, the command is printed, and the exit code is 1.
- **Other unexpected errors** in single mode and with `-l` fail only their URL, instead of ending the run. A system error prints one `Error: ...` line; anything else prints its traceback and asks for a bug report.
- **Videos without codec information** are no longer refused by the wizard as images.
- **Carousel images** show their real title in the item picker, not `(image #N)`.
- **A lone image in the wizard** stops at once with exit 0. It used to go through six questions and exit 1.
- **Links that only contain `x.com` in their name** (Dropbox, Box, Fox, Netflix, and the `fixupx.com`, `vxtwitter.com` and `fxtwitter.com` mirrors) are no longer shown as `x` in the wizard's banner, and are no longer asked for cookies before the probe.
- **Pressing `b` more than once** at the cookies prompt before the probe no longer ends in a traceback; each press goes back to the URL.

## Known limitation

Carousel images are still not saved: they are skipped, and the run reports them.
