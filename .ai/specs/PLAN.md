## Next release

**0.2.0 shipped on 2026-11-06.** It carried the keyring, carousel, `-p` and `-l` fixes, `curl_cffi`, and `ci-on-push`. It was a minor bump because `AGENTS.md` counts new messages as minor: there were 4 new ones, and `--cookies` now takes `BROWSER[+KEYRING]`. Nothing was breaking.

**0.3.0 is on `main` and pushed.** Rows 09, 17, 18, 19, 20, 21, 27, 29, 28, 26, 10 and 15 are merged and on `origin/main`, pushed by the orchestrator under the human's approval and delegation; the last code merges are `a6f31bf` (26), `025b40c` (10) and `f7d6439` (15). `origin/main` is `36f28a2`; local `main` is ahead only by plan and pipeline commits. CI passed on every merge up to `8f24c5f` (run 42435709897, Pages 42435709966); run 42441872866, on `36f28a2`, was in progress when this plan was written. Row 26's other half, retrying an empty `--cookies` run, was closed by its spec (D4): nothing reproduces it. 0.3.0 is a minor bump: `--playlist-items` is a new flag, and specs 18 to 21 and 26 to 29 add messages (`untagged`, `no_cover`, `cookies_no_browser` and `cookies_unreadable` among them); no flag or message was removed (`comm -23` on `v0.2.0..HEAD`). Nothing is breaking. The release notes must say:

- The equivalent command printed after a run always carries `-y` and stays in direct mode. It isn't printed after a cancelled run.
- `--playlist-items` is new. In 0.2.0, `--p` through `--playlis` resolved to `--playlist`. They're now ambiguous and exit 2.
- `-p` on a URL that holds a single video saves it under the same name as without `-p`, not `NA - <title> [<id>]`. Re-running such a download after upgrading saves one new copy next to the old file.
- `-s` now embeds subtitles in the video, and the subtitle files are still saved. `--sub-langs` alone now turns subtitles on. In mp4 the first language is marked as the default track; mkv and webm mark none.
- In the wizard, `.m4a` and `.wav` pages, and `.ogg` pages whose source names an audio codec, now convert to the audio format in `~/Music`. They used to land raw in `~/Videos`.
- In the wizard, some files are labelled as audio by the server or page but come in a container that can hold a video: `.ogg`, `.wma`, `.m4b`, `.asf`, `.mp4` or `.webm`, sent as `audio/*` or in `<audio>`. These now show `Audio` with a note and the video/audio choice. Enter keeps the file as served in `~/Videos`, as 0.2.0 and `-y` do; 2 gives an mp3. `.mp3`, `.m4a`, `.wav`, `.flac`, `.aac` and `.opus` keep the audio flow and convert to `~/Music`.
- The wizard now asks for cookies when the probe hits a login wall, and shows the site's reason. It walks every URL passed, not only the first, and says which ones it skipped. Videos without codec info are no longer refused as images.
- Image rows in the carousel picker show the entry's real title, not `(image #N)`.
- In the wizard, a lone image stops at once with exit 0. It used to go through six questions and exit 1.
- Files that ffmpeg can't write tags to (`.ogx`, `.weba`, `.m4r`, `.f4a`, `.f4b`, links with no extension, renamed files) were reported as `Download failed`, exit 1, though they were saved. They now end in `Done.`, with a warning that the file has no metadata and that running the same download again may save a second copy. `-p` no longer counts such items twice.
- A `-p` run in which every item fails now says `Download failed` and exits 1, instead of saying `Done.` and exiting 0.
- In the wizard, an `<audio>` tag on a file with no extension now shows the video/audio choice. Enter keeps the file as served.
- `-a` no longer fails over the cover image. A page whose image link is relative crashed with a traceback; `-f opus` on systems without `python-mutagen`, and a broken image, failed the download with the audio on disk. All of these now save the audio and say `<file>: saved without a cover image.` `-f wav`, which can't hold a cover, no longer asks for one, so it no longer fails on every video that has a thumbnail.
- Thumbnails are now fetched as `<name>.cover.<ext>`, aren't left behind after a failed download, and a playlist's own thumbnail is no longer saved next to its tracks. `-a` no longer deletes a user's own `<title>.jpg` in the output folder; a file already named `<title>.cover.jpg` is still replaced, as yt-dlp does.
- When `--cookies` names a browser that isn't installed, or whose cookies can't be read, the run says so and goes on without cookies in every mode. `-p`, `--playlist-items` and the carousel picker used to end in a traceback with exit 1; `-l` used to fail. Single mode no longer says `Failed with <browser> cookies` or adds a keyring hint that doesn't apply. A run that saves without them prints its command without `--cookies`.
