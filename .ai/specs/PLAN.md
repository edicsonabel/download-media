# Plan

The roadmap, owned by the planner (`/roadmap`). The architect turns a row into a spec (`NN-<id>.md`) when the human runs `/feature <id>` or `/fix <id>`.

## Statuses

`backlog` → `spec` → `in progress` → `done` → `shipped <version>` · `dropped`

Priority: `P1` broken or misleading today · `P2` clear value · `P3` nice to have. Size: `S` · `M` · `L`.

## Next release

**0.2.0 shipped on 2026-11-06.** It carried the keyring, carousel, `-p` and `-l` fixes, `curl_cffi`, and `ci-on-push`. It was a minor bump because `AGENTS.md` counts new messages as minor: there were 4 new ones, and `--cookies` now takes `BROWSER[+KEYRING]`. Nothing was breaking.

**0.3.0 is a minor because of what is already on `main`:** `equivalent-direct` added the user-visible `--playlist-items` flag (`8cc3d30`). That flag also makes `--p` through `--playlis` ambiguous: they resolved to `--playlist` in 0.2.0 and now exit 2, so the 0.3.0 notes must say so.

**Next:** the five `P1` rows outrank the rest of the list, in this order: `probe-no-codec`, `probe-auth`, `wizard-multi-url`, `playlist-items-fix`, `subs-as-documented`. `playlist-items-fix` has to merge before `/release`, so the new flag doesn't ship with those gaps. Then `workflow-pins`, because a release runs through the uncapped `deploy-aur.yml`, then `release-runbook` and `i18n-leftovers`. `release-runbook` no longer blocks `/release`, since `8cc3d30` is a `feat` and its current rule gives a minor too. `i18n-leftovers` no longer decides the bump, so it can slip without changing the version.
